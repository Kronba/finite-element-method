## 2. 讲义算法地图

讲义共 9 章、1079 页，主线是“从 1D 到 2D、从椭圆到抛物/双曲、从标量到向量、从定常到非定常、从线性到非线性”，并且**始终要求手写装配**（这是它最大的教学价值，也是选库时最重要的约束）。

### 2.1 逐章一览

| 章 | 数学问题 | 离散 | 核心算法 | 讲义自带算例 | 实现难点 |
|---|---|---|---|---|---|
| **Ch1** | 1D 二阶椭圆 `-(c u')' = f`，Dirichlet / Neumann / Robin | P1、P2 Lagrange | 参考单元、Gauss 积分、单元刚度矩阵、全局组装、边界条件 | Ex1 `c=e^x`，精确解 `u=x·cos x`，P1 误差 2.33e-3 → 2.29e-6；Ex2 同题 P2；Ex3 Neumann；Ex4 Robin | 变系数 `c(x)` 的积分；Neumann/Robin 的边界项；收敛阶验证 |
| **Ch2** | 无 PDE，纯离散基础 | 2D 矩形/三角形 P1/P2、Q1/Q2；3D 四面体/六面体 | 基函数构造、DOF 编号、数值积分、单元映射 | 无（为后续章节铺垫） | 局部→全局自由度映射；单元类型统一接口 |
| **Ch3** | 2D `-∇·(∇u)=f`，Ω=[-1,1]² | P1、P2 三角形 | 同 Ch1 的 2D 版本；Dirichlet/Neumann/Robin | Ex1 `u=xy(1-x²)(1-y)e^{x+y}`：P1 L2 6.83e-3→2.69e-5（O(h²)）、H1 O(h)；P2 L2 O(h³) | 2D 边界积分；L2/H1 误差计算；收敛表 |
| **Ch4** | 2D 抛物 `u_t-∇·(c∇u)=f`；二阶双曲 `u_tt-∇·(c∇u)=f` | 空间 P1/P2 + θ-格式 | 质量矩阵、刚度矩阵、θ-格式时间推进、稳定性 | Ex1 Ω=[0,2]×[0,1]，`c=2`，`u=e^{x+y+t}`；θ=1 后退 Euler 取 Δt=4h²；θ=1/2 Crank–Nicolson 取 Δt=h | 时间步与空间步匹配；初值/边界随时间变化；质量矩阵与刚度矩阵分离 |
| **Ch5** | 2D 线弹性 `-∇·σ(u)=f`，λ=1、µ=2，四边固支 | 向量值 P1/P2 | 应变-位移矩阵 B、平面应力/应变、向量值基函数 | Ex：`u1=sin(πx)sin(πy)`、`u2=x(x-1)y(y-1)`；P1 O(h²)/O(h)，P2 O(h³)/O(h²) | 张量运算；向量值 DOF 排布；应力恢复 |
| **Ch6** | 2D 定常 Stokes | Taylor–Hood（P2 速度 + P1 压力） | 鞍点系统、块矩阵、Schur 补、直接/迭代求解 | 精确解 `u1=x²y²+e^{-y}`、`u2=-(2/3)xy³+2-π sin(πx)`、`p=-(2-π sin(πx))cos(2πy)`，Ω=[0,1]×[-0.25,0] | inf-sup 条件；压力零空间；块预处理 |
| **Ch7** | 2D 定常 Navier–Stokes（ν=1） | Taylor–Hood + Newton | Newton 线性化、对流项、线性求解器 | 与 Ch6 同几何、同精确解 | Newton 收敛域；初值；雅可比矩阵装配 |
| **Ch8** | 2D 非定常 Stokes / 线弹性 | Taylor–Hood / P1 + θ-格式 | 时间推进 + 每个时间步解鞍点系统 | 精确解 = Ch6 解 × `cos(2πt)`，f 含 `-2π(...)sin(2πt)` | 时间相关边界与源项；长时间积分稳定性 |
| **Ch9** | 2D 非定常 NS | Taylor–Hood + Newton + 后退 Euler | 全耦合 Newton、时间推进 | 同 Ch6 精确解；另有“独立研究题目”：自造 f/初值/边界，取 h=1/8,1/16,1/32，Δt=8h³ | 全耦合系统规模；非线性+时间双层迭代；性能 |

### 2.2 从讲义抽象出的“实现组件”

把 9 章拆成可复用的软件组件，这也是后面所有库选型与项目结构的依据：

1. **网格（Mesh）**：1D 区间、2D 矩形/三角形、3D 六面体/四面体；均匀加密与局部加密。
2. **有限元空间（FE Space）**：P1/P2、Q1/Q2、向量值（弹性）、混合（Taylor–Hood）。
3. **求积（Quadrature）**：1D/2D/3D Gauss–Legendre；三角形/四面体求积。
4. **装配（Assembly）**：单元刚度/质量矩阵、右端项、边界项；局部→全局。
5. **边界条件**：Dirichlet（消元/置大数）、Neumann、Robin。
6. **线性代数**：稀疏矩阵、直接法（小规模）、Krylov + 预条件（大规模）。
7. **时间推进**：θ-格式（θ=1 后退 Euler、θ=1/2 Crank–Nicolson）。
8. **非线性求解**：Newton（Ch7、Ch9）。
9. **后处理**：L2/H1/L∞ 误差、收敛阶表、VTK 可视化。

> **选库判据**：库必须让 1–9 每一步都“看得见、改得动”。这正是 deal.II（FEValues 显式装配）优于 FEniCSx（UFL 自动生成）的地方——后者抽象掉了装配细节，适合做研究，不适合学“实现”。

### 2.3 讲义自带算例的收敛阶（用于验收）

| 章 | 单元 | 量 | 理论阶 | 讲义实测（最细网格） |
|---|---|---|---|---|
| Ch1 | P1 | L2 | 2 | 2.29e-6（h=1/128） |
| Ch1 | P2 | L2 | 3 | 4.66e-11 |
| Ch3 | P1 | L2 / H1 | 2 / 1 | 2.69e-5 / 1.18e-2 |

### 3.3 推荐方案

**主线：deal.II 9.8 + Eigen + PETSc（+ hypre/Trilinos 可选）。**

理由：

1. **教程即教材**：deal.II 的 step 系列与讲义章节几乎一一对应（见下表），可以“一章讲义 + 一个 step”对照学习；
2. **装配透明**：`FEValues`、`FE_Q`、`DoFHandler`、`SparsityPattern` 这些概念与讲义第 2 章讲的“基函数、DOF 编号、稀疏结构”完全同构；
3. **生态完整**：PETSc/Trilinos 后端、p4est 分布式网格、Kokkos GPU、VTK 输出一应俱全；
4. **许可友好**：LGPL-2.1+，动态链接即可用于闭源项目（需注意 LGPL 义务）。

**备选/补充：MFEM 4.10**，用于两件事：

- 高性能对比实验（同一算例，deal.II vs MFEM 的组装/求解时间）；
- GPU 实验（`ex1p`、`ex2p` 的 CUDA/HIP 版本），讲义没有覆盖，但作为“企业级”能力值得了解。

**不推荐作为主线：FEniCSx**。它是“写弱形式 → 自动生成代码”的路线，会把讲义最想训练的“装配—编号—积分”全部隐藏掉；但可以在第 9 章“独立研究题目”阶段用它快速做参数扫描。

## 4. 线性代数与并行/分布式计算栈

### 4.1 Eigen 的定位

- **适用**：Ch1–Ch5 的手写装配（几千~几万 DOF）、稠密小系统、单元级矩阵运算、单元测试里的参考解。
- **不适用**：Ch6–Ch9 的大规模三维问题（Eigen 的稀疏直接法在 2D 几万 DOF 内尚可，3D 会爆内存），以及分布式并行。
- **推荐用法**：`Eigen::SparseMatrix<double>` + `Eigen::SimplicialLDLT` / `SparseLU`；与 deal.II 对比时作为“手写基准”。
- 版本：apt 提供 3.4.0，官网最新 5.0.0（2025-09-30，要求 C++14）。**建议先用 3.4.0**，5.0 的 API 有少量破坏性变更，且与 deal.II 的兼容性需验证。

### 4.2 并行/分布式栈的分层

```
应用层        deal.II / MFEM
             ↓
离散层        p4est（分布式网格）、METIS/ParMETIS（分区）
             ↓
线性代数层    PETSc（KSP/PC/SNES/TS）、Trilinos（Belos/Ifpack2/MueLu）
             ↓
预条件/直接法 hypre（BoomerAMG）、MUMPS、SuperLU_DIST、UMFPACK（串行）
             ↓
通信层        MPI（OpenMPI 4.1.6 / MPICH）
             ↓
加速层        OpenMP、Kokkos、CUDA/HIP
```

### 4.3 各组件的角色与版本

| 组件 | apt 版本 | 最新版 | 在本项目中的角色 |
|---|---|---|---|
| OpenMPI | 4.1.6 | 5.x | 分布式内存通信；deal.II/MFEM/PETSc 的并行基础 |
| PETSc | 3.19.6 | 3.26.1 | 大规模稀疏求解：KSP（CG/GMRES）、PC（AMG/ILU）、SNES（Newton）、TS（时间推进） |
| hypre | 2.28.0 | 2.32/3.1 | BoomerAMG 代数多重网格预条件，椭圆问题的“标配” |
| Trilinos | 13.2.0 | 17.3 | Belos（Krylov）、Ifpack2（预条件）、MueLu（AMG）、AMESOS2（直接法） |
| MUMPS | 5.6.2 | 5.7+ | 并行稀疏直接法，二维问题很实用 |
| SuperLU_DIST | 8.2.1 | 9.x | 分布式稀疏直接法 |
| METIS/ParMETIS | 5.1.0 | 5.1.0 | 图分区；ParMETIS 为非商业免费许可，商用需注意 |
| Gmsh | 4.12.1 | 4.13+ | 复杂几何网格生成；**GPL 许可，链接其 SDK 有传染性**，建议“外部调用”而非链接 |

### 4.4 选型建议（按阶段）

- **阶段 1（Ch1–Ch5）**：只用 Eigen + 手写装配，**不要**引入 PETSc/Trilinos，避免“还没学会装配就先学并行”。
- **阶段 2（Ch6–Ch7）**：引入 deal.II 自带求解器 + UMFPACK（二维鞍点系统直接法足够）；同时用 PETSc 做对比。
- **阶段 3（Ch8–Ch9）**：MPI + PETSc（GMRES + AMG/ILU），必要时 MUMPS 直接法兜底。
- **阶段 4（企业级）**：Trilinos（MueLu）或 hypre（BoomerAMG）做 scalable 预条件；GPU 用 Kokkos/MFEM。

## 5. 数值算例：与讲义算法一一对应的外部基准

### 5.1 两类算例，别混用

| 类型 | 目的 | 判据 | 例子 |
|---|---|---|---|
| **验证（verification）** | 证明代码解的是“对的方程” | 有精确解 → 收敛阶 = 理论阶 | 制造解（MMS）、讲义自带算例 |
| **确认（validation）** | 证明模型符合“物理/工程现实” | 有公认参考值 → 误差在文献范围内 | Ghia 顶盖驱动、DFG 圆柱绕流、Cook 膜 |

**建议**：每章先做 verification（收敛表），再做 1 个 validation（与文献值对比）。前者抓 bug，后者抓建模错误。

### 5.2 逐章算例映射

| 章 | 讲义自带（verification） | 外部基准（validation / 更严格的 verification） | 对比量 |
|---|---|---|---|
| **Ch1** 1D 椭圆 | `c=e^x`, `u=x·cos x`；P1/P2 收敛表 | **MMS**：取 `u=sin(πx)`，则 `f=π²sin(πx)`，边界由 u 给出；h=1/2…1/64 验证 O(h²)/O(h³) | L2/H1 误差、收敛阶 |
| **Ch2** 基函数/DOF | 基函数图像、单位分解 `Σφᵢ=1` | **Patch test**（常应变分片试验，Irons & Razzaque 1972）：任意扭曲网格上线性场必须精确重现 | 节点值误差 ~1e-14 |
| **Ch3** 2D Poisson | `u=xy(1-x²)(1-y)e^{x+y}` | ① **MMS**：`u=sin(πx)sin(πy)`；② **L 形区域**：`u=r^{2/3}sin(2θ/3)`（角点奇性，自适应加密基准）；③ 间断系数界面问题 | L2/H1 阶；L 形区域收敛率退化到 ~h^{2/3} |
| **Ch4** 抛物/双曲 | `u=e^{x+y+t}`，θ=1 与 θ=1/2 | ① **热方程 MMS**：`u=e^{-2π²t}sin(πx)sin(πy)`，验证时间阶 1/2；② **波动方程**：`u=sin(πx)cos(πt)`，验证 Crank–Nicolson 的二阶 | Δt 收敛阶、能量守恒 |
| **Ch5** 线弹性 | `u1=sin(πx)sin(πy)`, `u2=x(x-1)y(y-1)` | ① **Cook 膜**（Cook, Malkus & Plesha 1989）：E=1, ν=1/3，平面应力，自由端竖向位移收敛值 ≈ 23.96；② **Kirsch 圆孔**：无限板圆孔，Kt=3，用精确解施加远场牵引；③ **NAFEMS LE10** 薄板带孔 | 尖端位移、孔边应力集中系数 |
| **Ch6** 定常 Stokes | 讲义精确解（`x²y²+e^{-y}` 等） | ① **Poiseuille/Couette** 精确解；② **DFG 2D-1（Re=20）** 圆柱绕流（低 Re 下接近 Stokes）；③ Taylor–Hood 的 MMS 收敛表 | 速度/压力误差、阻力系数 |
| **Ch7** 定常 NS | 同 Ch6 精确解 + Newton 收敛史 | ① **Ghia 顶盖驱动**（Ghia, Ghia & Shin 1982）：Re=100/400/1000，中心线速度剖面；② **DFG 2D-2（Re=100）**：CD、CL、Δp；③ **后台阶**（Armaly 1983）再附长度 | 中心线 u(y)、CD/CL、再附长度 |
| **Ch8** 非定常 Stokes/弹性 | 精确解 × `cos(2πt)` | ① **Taylor–Green 涡**（衰减精确解，验证时间精度与耗散）；② 周期驱动方腔（Stokes 第二问题）；③ 弹性杆纵波（一维波动精确解） | 时间收敛阶、相位/幅值误差 |
| **Ch9** 非定常 NS | 讲义“独立研究题目”（自造 f/初值/BC） | ① **DFG 2D-3（Re=200，非定常）**：Strouhal 数、升阻力幅值；② **Re=10000 方腔**（2D 非定常，Ghia 数据仅到 Re=3200/5000/10000 的稳态）；③ **Taylor–Green 涡 Re=100/1600** 的 DNS 参考解 | St、CD/CL 幅值与频率 |

> 说明：Ch6–Ch9 的讲义精确解本身就是“制造解”，与 DFG/Ghia 这类“无解析解但有公认参考值”的基准互补——前者查实现，后者查物理。

### 5.3 各基准的获取方式

| 基准 | 权威来源 | 参考值形式 | 备注 |
|---|---|---|---|
| MMS（制造解） | Salari & Knupp, *Code Verification by the Method of Manufactured Solutions*, SAND2000-1004；Oberkampf & Roy, *Verification and Validation in Scientific Computing*, CUP 2010 | 解析解 + 收敛阶 | 自己构造即可，无需数据文件 |
| L 形区域 | 自适应 FEM 文献（Babuška & Suri；Dörfler 标记策略）；deal.II step-6 | 收敛率、自适应网格 | 角点奇性指数 2/3 |
| Patch test | Irons & Razzaque (1972)；Zienkiewicz《FEM》教材 | 常应变精确重现 | 十行代码可测 |
| Cook 膜 | Cook, Malkus & Plesha (1989)；大量 FEM 论文复现 | 自由端竖向位移 ≈ 23.96（细网格） | 检验剪切自锁/单元畸变 |
| Kirsch 圆孔 | Kirsch (1898) 解析解；有限域版本见 FEM 基准文献 | 应力集中系数 Kt=3（无限板） | 用解析解施加远场边界 |
| NAFEMS LE10 | NAFEMS 基准报告（1986 起） | 孔边最大 von Mises 应力 | 工业界常用验收题 |
| Ghia 方腔 | Ghia, Ghia & Shin, *J. Comput. Phys.* 48 (1982) 387–411 | 中心线 u(y)、v(x) 表格（Re=100…10000） | 稳态 NS 的“金标准” |
| DFG 圆柱绕流 | Schäfer & Turek (1996)；featflow 基准网站 | CD、CL、Δp、St；2D-1/2/3 | 非定常版本给出 Strouhal 数 |
| Taylor–Green 涡 | 经典 NS 精确解；DNS 文献（如 Re=1600） | 动能衰减曲线 | 检验数值耗散 |

### 5.4 如何在工程里组织这些算例

- **每个算例一个可执行文件**：`apps/ch03_lshape.cpp`、`apps/ch07_ghia.cpp`，通过 `--h 1/64 --order 2 --output vtk` 参数化；
- **每个算例一份“参考数据”**：CSV 放在 `tests/data/`，用 `ctest` 做容差比较（不要硬编码在源码里）；
- **收敛表自动生成**：`apps/` 输出 CSV → Python 脚本画 log-log 图 → 报告；
- **基准结果入库前先跑 verification**：收敛阶不对，先别信 validation 数字。

## 6. CMake 企业级专业使用教程（调研版）

本节先给“原则 + 骨架 + 关键片段”，完整长教程作为下一阶段交付物。

### 6.1 五条硬原则

1. **一切挂在 target 上**：`target_sources / target_include_directories / target_compile_options / target_link_libraries`，**禁止**全局 `include_directories()`、`link_libraries()`、`CMAKE_CXX_FLAGS` 追加。
2. **可见性显式化**：`PRIVATE`（只自己用）、`INTERFACE`（只给消费者）、`PUBLIC`（两者）；依赖通过 `INTERFACE_*` 属性传递。
3. **不 glob 源文件**：`file(GLOB ...)` 会让新增文件不触发重新配置；显式列文件（或 CMake 3.28+ 的 `CONFIGURE_DEPENDS` 兜底）。
4. **namespace + config 包**：对外导出的 target 必须带命名空间（`fem::core`），并配套 `find_package(fem)` 的 config 文件；第三方库优先用其自带的 `Foo::Foo`。
5. **一份 Presets 走天下**：本地、CI、HPC 用同一套 `CMakePresets.json`，差异只体现在 preset 里。

> 背景：CMake 4.0（2025）**删除了对 policy version < 3.5 的兼容**，大量老项目因此报错（Fedora 44 升级时 2,359 个 CMake 包中有 776 个受影响，绝大多数只需把 `cmake_minimum_required` 提一行）。所以“最低版本”这件事在 2026 年必须认真写。

### 6.3 依赖管理：先系统包，再 vendor，最后才 vendor 源码

| 依赖 | 推荐方式 | 说明 |
|---|---|---|
| Eigen 3.4 | `find_package(Eigen3 3.4 REQUIRED NO_MODULE)` → `Eigen3::Eigen` | 头文件库，apt 装即可 |
| MPI | `find_package(MPI REQUIRED COMPONENTS CXX)` → `MPI::MPI_CXX` | **不要**手写 `mpicxx`；imported target 会处理编译器包装器 |
| deal.II 9.x | `find_package(deal.II 9.5 REQUIRED HINTS ${DEAL_II_DIR})` → `deal.II::deal.II` | 官方 config 包，内部还会做编译器/特性检查 |
| MFEM 4.x | `find_package(MFEM REQUIRED)` → `mfem` | 装在 `lib/cmake/mfem` |
| PETSc | **pkg-config**：`pkg_check_modules(PETSc REQUIRED IMPORTED_TARGET PETSc)` | PETSc 至今没有一等公民的 `PETScConfig.cmake`，这是行业现实 |
| METIS/ParMETIS | 自己写 `cmake/FindMETIS.cmake` | CMake 没有内置 Find 模块 |
| Gmsh | 外部 CLI 调用，**不要链接 SDK** | GPL 传染性 |

PETSc 的正确写法（承认现实）：

```cmake
find_package(PkgConfig REQUIRED)
pkg_check_modules(PETSc REQUIRED IMPORTED_TARGET PETSc)
target_link_libraries(fem_core PUBLIC PkgConfig::PETSc)
```

> 常见坑：`FindMPI` 与 `mpicxx` 混用会重复链接；`HDF5` 仍是变量式（`HDF5_INCLUDE_DIRS`/`HDF5_LIBRARIES`），没有官方 imported target，用前先 `find_package(HDF5)` 并检查版本。

**什么时候该 vendor**：

- 小、头文件、无 MPI/GPU 依赖（如 Catch2、fmt、spdlog）→ `FetchContent`，`GIT_TAG` **钉到 commit hash**（不要 `main`）；
- 大、带 MPI/GPU/ABI 要求（PETSc、Trilinos、deal.II、hypre）→ **系统包 / Spack / vcpkg / Conan**，让编译器和 MPI 与集群一致。用 FetchContent 拉 MPI 库是典型的“能编过、跑不对”。

```cmake
include(FetchContent)
FetchContent_Declare(Catch2
  GIT_REPOSITORY https://github.com/catchorg/Catch2.git
  GIT_TAG        v3.7.1        # 用 release tag 或 commit hash
  GIT_SHALLOW    TRUE)
FetchContent_MakeAvailable(Catch2)
```

企业级可复现性：vcpkg manifest（`vcpkg.json` + `"builtin-baseline"`）或 Conan 2（`CMakeToolchain` + `CMakeDeps` + lockfile）。二选一即可，不要两套并存。

### 6.5 编译选项：用 INTERFACE target 统一注入

```cmake
# cmake/CompilerWarnings.cmake 或直接写在顶层
add_library(fem_warnings INTERFACE)
target_compile_options(fem_warnings INTERFACE
  $<$<CXX_COMPILER_ID:GNU,Clang>:-Wall;-Wextra;-Wpedantic;-Wshadow;-Wconversion>
  $<$<CXX_COMPILER_ID:MSVC>:/W4>)

if(FEM_WARNINGS_AS_ERRORS)
  target_compile_options(fem_warnings INTERFACE
    $<$<CXX_COMPILER_ID:GNU,Clang>:-Werror>)
endif()

# src/CMakeLists.txt
add_library(fem_core STATIC mesh.cpp fe_space.cpp assembly.cpp time_stepper.cpp)
add_library(fem::core ALIAS fem_core)
target_include_directories(fem_core
  PUBLIC
    $<BUILD_INTERFACE:${PROJECT_SOURCE_DIR}/include>
    $<INSTALL_INTERFACE:${CMAKE_INSTALL_INCLUDEDIR}>)
target_link_libraries(fem_core
  PUBLIC  fem_warnings Eigen3::Eigen
  PRIVATE )
```

> 3.23+ 还可以用 `target_sources(fem_core PUBLIC FILE_SET HEADERS BASE_DIRS include FILES ...)`，再用 `install(TARGETS fem_core FILE_SET HEADERS)` 安装头文件；FILE_SET 会自动推导 include 目录，省掉 `$<INSTALL_INTERFACE>`。两种写法选一种即可。

```cmake
if(FEM_SANITIZE)
  target_compile_options(fem_core PRIVATE -fsanitize=address,undefined -fno-omit-frame-pointer)
  target_link_options(fem_core PRIVATE -fsanitize=address,undefined)

```

### 6.9 CI（GitHub Actions 骨架）

```yaml
name: ci
on: [push, pull_request]
jobs:
  build:
    strategy:
      matrix:
        preset: [debug, release, asan]
    runs-on: ubuntu-24.04
    steps:
      - uses: actions/checkout@v4
      - uses: hendrikmuhs/ccache-action@v1
      - run: sudo apt-get update && sudo apt-get install -y ninja-build libeigen3-dev libopenmpi-dev
      - run: cmake --preset ${{ matrix.preset }}
      - run: cmake --build --preset ${{ matrix.preset }}
      - run: ctest --preset ${{ matrix.preset }} --output-junit junit.xml
      - uses: actions/upload-artifact@v4
        if: always()
        with: { name: junit-${{ matrix.preset }}, path: junit.xml }
```

要点：缓存 **ccache** 而不是 build 目录；`ctest --output-junit` 产出可被 CI 解析的报告；MPI 测试用 `mpiexec -n 4` 并打 `mpi` 标签，默认 `ctest -LE mpi` 跳过。

### 6.10 十个常见坑（本项目会遇到的）

1. `cmake_minimum_required(VERSION 4.3)` + apt 的 CMake 3.28 → 直接失败（见 §7.3）。
2. CMake 4.x 下老依赖报 “Compatibility with CMake < 3.5 has been removed” → 升级依赖或临时 `-DCMAKE_POLICY_VERSION_MINIMUM=3.5`（只是救急）。
3. `find_package(PETSc)` 找不到 → PETSc 没有 config 包，用 pkg-config。
4. 链接 MPI 库时同时 `-lmpi` 和 `mpicxx` → 符号重复/ABI 混乱；只用 `MPI::MPI_CXX`。
5. `file(GLOB)` 新增源文件不重配 → 显式列表。
6. `CMAKE_BUILD_TYPE` 为空 → Release 优化没开，性能测试全是假的；用 Presets 固定。
7. `-march=native` 写死在工程里 → 换机器 illegal instruction；放到 preset 的 `CMAKE_CXX_FLAGS_RELEASE`。
8. `install()` 用相对路径但没 `GNUInstallDirs` → 32/64 位 libdir 错位。
9. RPATH 没设 `$ORIGIN` → 安装后必须 `LD_LIBRARY_PATH` 才能跑。
10. 用 `add_definitions(-D...)` 全局宏 → 改用 `target_compile_definitions`，并区分 PUBLIC/PRIVATE。

### 7.2 三条安装路线

**路线 A：apt 快速起步（推荐先走这条，需你本人执行 `sudo`）**

```bash
sudo apt update
sudo apt install -y build-essential cmake ninja-build gdb \
    libeigen3-dev libopenmpi-dev openmpi-bin \
    petsc-dev libpetsc-real-dev \
    libdeal.ii-dev libmfem-dev \
    libhypre-dev libmumps-dev libsuitesparse-dev libmetis-dev \
    libhdf5-dev libvtk9-dev gmsh libgmsh-dev
```

- 优点：10 分钟内可用，依赖关系自动解决；
- 缺点：版本旧（deal.II 9.5.1、MFEM 4.5.2、PETSc 3.19.6），且 `cmake` 是 3.28.3，**与现有 `cmake_minimum_required(VERSION 4.3)` 冲突**；
- 处理：把 `CMakeLists.txt` 的最低版本改为 `3.25`（或 `3.28`），或改走路线 B 装 CMake 4.4。

**路线 B：源码编译最新版（推荐作为“企业级”主线）**

1. CMake ≥ 4.3：从 Kitware APT 源安装，或 `pip install cmake`（Python 3.12 可用），或下载官方二进制；
2. OpenMPI 4.1.6（apt 即可）；
3. PETSc 3.26（`--with-debugging=0 --with-optimization=1 --download-hypre --download-mumps`）；
4. deal.II 9.8（`cmake -DDEAL_II_WITH_MPI=ON -DDEAL_II_WITH_PETSC=ON -DDEAL_II_WITH_TRILINOS=OFF`）；
5. MFEM 4.10（`make serial -j8` / `make parallel -j8`）。

- 优点：版本新、可定制、与 CI 一致；
- 缺点：deal.II 全量编译在 24 核上约 30–60 分钟，**峰值内存可能超过 15 GiB**，建议 `-j8`（不是 `-j24`）。

**路线 C：Spack（HPC 标准做法，可作为进阶）**

```bash
git clone https://github.com/spack/spack.git
. spack/share/spack/setup-env.sh
spack install dealii@9.8.0 +mpi +petsc ^openmpi@4.1.6
```

- 优点：多版本共存、MPI 变体管理、可复现；
- 缺点：学习成本高、首次编译慢。

### 7.3 CMake 版本冲突的三种解法

1. 改项目：`cmake_minimum_required(VERSION 3.28...4.4)`（最省事；apt 的 3.28.3 能过，4.x 也能过，且已支持 Presets v6、`FILE_SET`、`target_link_libraries` 全部现代写法）；
2. 装新版 CMake：Kitware APT 源（`https://apt.kitware.com/`）或 `pip install cmake==4.4.2`；
3. 用 CLion 自带 4.4.2 作为 `CMAKE_COMMAND`（当前项目实际就是这么跑的，见 `cmake-build-debug/CMakeCache.txt`）。

> 建议：**项目最低版本写 3.25，CI 用 4.4**。这样本地 apt 环境和最新 CI 都能跑，也符合“企业级”对可移植性的要求。
